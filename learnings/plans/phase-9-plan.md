# Plan: Phase 9 - Packaging, Native Build Lane, and Release Setup

## Goal
Turn the completed Rabbit codebase into a real packageable desktop app path by replacing the placeholder frontend build, wiring the Tauri packaging baseline, and defining the Mac release lane.

## Current state at Phase 9 start
- Phases 4 to 8 are complete.
- The clone now has strong parity in:
  - shell behavior,
  - tasks/projects/views/inbox,
  - calendar and scheduling,
  - API/sync/cache behavior,
  - native shell contracts, Mac shell fit, and hardening.
- The packaging path is still incomplete:
  - `apps/desktop/scripts/build.mjs` is still a placeholder,
  - `tauri.conf.json` points at the source tree instead of a built desktop bundle,
  - there is no packaged `.app`, `.dmg`, or native desktop output,
  - Rust/Tauri verification cannot run yet on this machine because the Rust toolchain is missing.

## Execution mode

Use `/steps` for one numbered step at a time.

## Approach
This phase is the source-to-artifact pass.

Keep the clone behavior stable and improve:
- the real frontend bundle path,
- the native Tauri build entrypoints,
- the Mac packaging and signing lane,
- the packaging verification story.

## Edge cases

- TypeScript emit works but native packaging still cannot run:
  keep the artifact path honest and document the missing Rust/Mac prerequisites instead of pretending packaging is complete.

- Tauri config expects a dev server later:
  keep the build path explicit for production and defer dev-server ergonomics if they are not needed yet.

- Packaging scripts accidentally depend on local machine state:
  add preflight checks and fail with readable messages.

## Risks

- This phase can drift into full release engineering.
  Mitigation: focus only on the build-to-artifact path and the minimum release-lane scaffolding needed to make it believable.

- Native tooling gaps can block forward motion.
  Mitigation: make the frontend build real first, then isolate Rust/Mac-specific limits clearly.

## Done when

- `apps/desktop/dist/` is generated by a real desktop build step.
- Tauri build config points at built frontend artifacts instead of raw source.
- The Mac packaging/signing lane has explicit scaffolding and docs.
- `npm run desktop:build`, `npm run test`, `npm run typecheck`, and `npm run build` pass.
- The repo clearly states what still requires Rust or Mac hardware before claiming a final packaged app.
